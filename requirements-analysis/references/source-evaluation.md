# 来源、版本与冲突处理

## 可信度等级

| 等级 | 来源 | 用法 |
|---|---|---|
| A | 政府部门、监管机构、标准组织、项目业主、原始招标文件 | 可作为重要事实或约束依据，仍需核对适用范围和版本 |
| B | 厂商官网、正式白皮书、公开项目案例、专业机构报告 | 可作参考和案例证据，注意宣传性和选择性披露 |
| C | 专业媒体、研究文章、行业博客 | 用于背景和线索，重要结论需交叉验证 |
| D | 论坛、转载、搜索摘要、无署名内容 | 只能作线索，不作为重要结论的唯一依据 |

## 版本检查

记录发布日期、修订日期、生效日期、废止状态、适用地区、适用行业和访问日期。政策或标准出现多个版本时，分别登记，不直接覆盖旧版本；报告中说明采用版本及原因。

## 冲突处理

发现冲突时保留双方原文，记录来源、位置、冲突类型、影响范围、当前判断和待确认人。可以基于文件约束、时效性、适用范围和权威性提出建议，但不能把建议写成已确认需求。冲突状态至少使用：待核实、采用 A、采用 B、需要业主决策、已解决。

## 证据表达

每条重要结论使用“结论 + 证据 + 推理 + 限定条件”的结构。例如：某能力属于行业常见做法（结论），依据两个同类项目公开方案（证据），因为它们都解决相同的跨部门协同问题（推理），但是否纳入本项目仍取决于范围和预算（限定条件）。
