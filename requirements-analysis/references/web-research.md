# 互联网辅助研究

## 研究目标

互联网检索用于验证设计假设、补足行业背景、发现同类项目做法、核对政策标准版本和寻找可比较的验收指标。它不能替代项目原始资料，也不能自动增加建设范围。

## 检索流程

1. 从资料内的空白、冲突、模糊指标和技术决策生成研究问题。
2. 为每个问题设计 2—4 组关键词，包含业务词、行业词、地区词、项目类型词和文件类型词。
3. 先查官方和原始来源，再查案例、厂商资料和专业研究。
4. 对关键事实交叉验证，保存标题、机构、URL、发布日期、访问日期、摘录、结论和适用性。
5. 将外部发现映射到需求编号，说明影响、建议采用状态和决策人。

## 检索主题

- 竞品：`行业 + 系统/平台 + 功能模块/产品白皮书/官方文档`
- 同类项目：`行业 + 建设项目/招标文件/建设方案/验收`
- 政策标准：`主管部门/标准组织 + 主题 + 通知/办法/标准 + 最新`
- 业务流程：`行业场景 + 办理流程/审批流程/数据共享/监管`
- 技术与安全：`系统类型 + 等保/密评/数据安全/接口规范/灾备`

## 来源记录

每条外部来源记录：调研编号、问题、关键词、标题、发布机构、来源类型、URL、发布时间、访问时间、关键摘录、主要发现、可信度、适用地区/行业、关联需求、影响、建议动作和处理状态。页面内容可能变化，重要事实尽量保存可引用的原文片段或页面标题，不抓取受限内容。

## 输出规则

不要只输出“搜到了什么”，要输出“对项目有什么影响”。每项外部发现归入以下一种：建议采用、建议参考、建议暂不采用、需要验证、与项目无关。无法联网时明确写出未完成互联网研究，不能用模型记忆冒充搜索结果。
