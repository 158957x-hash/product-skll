# 竞品与案例对标

## 对标对象

优先选择与项目行业、用户角色、业务流程、监管环境或建设规模相近的对象。区分正式产品、已建项目、公开招标方案、行业平台、实验性方案和宣传材料，不能把不同类型对象直接并列排名。

## 对比维度

- 用户和组织：服务对象、角色、权限、协同方式。
- 业务和功能：核心流程、模块、办理、审批、查询、统计、移动端和运维。
- 数据：来源、标准、主数据、共享、质量、分析和留痕。
- 集成：认证、接口、消息、地图、设备、文件和外部平台。
- 技术和安全：部署、可用性、性能、灾备、审计、合规和扩展。
- 交付和运营：实施阶段、培训、服务、运维、验收和持续运营。

## 结论分层

对每个能力判断：行业通用能力、先进能力、本项目已有明确依据、本项目可选建议、暂不适用或资料不足。写明借鉴条件、潜在成本、实施风险、与现有系统的关系和不采用理由。竞品没有某功能不代表该功能不重要，案例出现某功能也不代表本项目必须建设。
